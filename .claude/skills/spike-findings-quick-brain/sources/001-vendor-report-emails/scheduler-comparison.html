Spike 001 · Scheduler Comparison

Five viable schedulers for weekly vendor-email composition. Each one is sufficient; the choice is downstream of where QuickBrain is being deployed and whether gbrain Minions over PGLite passes the Phase 4 spike.

Option Where it runs Pros Cons Verdict for QuickBrain v1.1
gbrain Minions
 Inside the Bun process, durable queue backed by PGLite Same process as the brain · deterministic · $0 token cost · survives crashes · Minions are first-class in gbrain PGLite + Minions interaction is unverified (Phase 4 spike resolves this) · cron-shaped scheduling needs a wrapper · no built-in dashboard BEST IF PHASE 4 SPIKE PASSES — natural home for any scheduled gbrain work
System cron / launchd
 OS-level, outside the app process Zero infra · persists across reboots · OS-native · already running on every Mac/Linux box Off-process: must invoke a CLI or webhook · logs land in syslog, not the app · operator setup is OS-specific · brittle when the box reboots and timezone shifts OK — easy for self-host VM, awkward for operator's laptop
Vercel Cron
 Vercel platform, declared in vercel.json Declarative · managed · zero infra · per-deployment Locks to Vercel hosting (not chosen) · minimum cron resolution is daily on hobby tier · no on-prem path N/A FOR v1.1 — we're not on Vercel; revisit if/when we host there
GitHub Actions cron
 GH Actions runners, outside the app Free · declarative YAML · easy to manage · can call a webhook into the deployed app · secrets live in GH Off-deployment infrastructure · known 5–15 min jitter on GH cron schedules · adds a deployment dependency on GH OK — works but feels overkill for a single-box demo VM
node-cron / croner (in-process)
 Inside the Next.js process Tight integration · can read lib/gbrain directly · zero new deps if we accept croner Dies on every Next.js restart · not durable · competes with HTTP for the event loop · anti-pattern in Next.js 15 App Router AVOID — fine for prototyping, fails on production-shaped restarts

Bottom line

For v1.1 we don't need to pick. The spike answers "is there a viable option?" — yes, multiple. Defer the actual scheduler choice to v1.2 ("Outbound Communications") and unblock by building the manual-trigger path first: a dashboard button "Compose this week's vendor emails" that runs the same composition pipeline on demand. That delivers ~80% of the value at ~10% of the complexity and leaves the cron decision downstream of the Phase 4 Minions spike result.
