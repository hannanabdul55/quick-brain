FINDING (would have bitten Phase 7 mid-execution): importFromContent requires the sourceId to ALREADY exist as a row in the sources table. gbrain enforces this via FK pages_source_id_fkey. The first run threw PostgresError: Key (source_id)=(qbo-spike-007) is not present in table "sources". Phase 7's QBO OAuth-connect handler must INSERT INTO sources (id, name, config) VALUES ($1, $2, $3::jsonb) ON CONFLICT DO NOTHING BEFORE the first ingest job is enqueued. This was not in any of the 9 Phase 7 plans.
Re-sync primitive simplified: Phase 7 D-08 "wipe-and-reingest" can be one SQL — DELETE FROM sources WHERE id = $1. The ON DELETE CASCADE on pages.source_id sweeps every page, chunk, tag, and link atomically. The cleanup probe at end of spike took 119ms.

Phase 7 implications

  1. Add one connect-time step: on QBO OAuth success, INSERT INTO sources (id, name, config) VALUES ('qbo-<userId>', '<display>', '{"kind":"qbo"}'::jsonb) before enqueuing the first ingest job.
  2. Extend types/gbrain.ts with a typed importFromContent(engine, slug, content, opts) wrapper that delegates to _load("import-file"). Pattern proven, zero runtime risk.
  3. Implement re-sync (D-08) as one SQL DELETE — no per-slug iteration. The destructive-confirm modal in UI-SPEC.md is gating exactly the right primitive.
  4. Plan a vendor-first ingest order: bills wikilink to [[companies/<slug>]] — emit company pages first or accept that link edges are filled in by a later reconcile pass.
