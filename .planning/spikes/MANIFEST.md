# Spike Manifest

## Idea

Two adjacent feasibility questions for QuickBrain post-v1.0:

1. **Vendor outbound emails** — Can QuickBrain compose and send weekly per-vendor activity summary emails on behalf of a small-business owner like Mara? The brain already knows what was bought from whom; the question is whether automated outbound email to vendors is (a) deliverable, (b) legally clean, (c) something the operator would actually trust without an approval gate.

2. **Easier accounting connectors than QuickBooks Online** — The v1.1 Phase 6 commits to QBO as the first live-data connector. But Xero, Wave, and FreshBooks all sit in adjacent SMB niches with different OAuth/API ergonomics. Can we identify a connector with simpler integration cost, broader fit, or better dev-experience than QBO? The answer informs whether Phase 6 stays QBO-only or grows a multi-connector abstraction.

## Requirements

Captured as user choices and findings emerge.

- **Vendor email path must have an approval gate** (no auto-send) — operator reviews each weekly batch before send. CAN-SPAM + trust + tone-policing all converge here. Source: spike 001.
- **Anomaly findings from `smb-audit` must NEVER auto-inject into vendor-facing email bodies.** They surface in the operator's digest only. Source: spike 001.
- **Reuse Resend** (already locked for Phase 5 magic-link) — no second email provider for outbound. Source: spike 001.
- **First implementation should be manual-trigger ("compose this week's emails"), not scheduled.** Cron decision is downstream of the Phase 4 Minions-over-PGLite spike. Source: spike 001.
- **v1.1 Phase 6 stays QBO-only.** Highest US SMB market share + best raw throughput + longest refresh tokens. Source: spike 002 head-to-head.
- **Name connector-agnostic types from day one** in `lib/connectors/types.ts` (proposed) — `Bill`, `Vendor`, `BankLine` shapes shared across QBO + future Xero adapter. Avoid retro-fit cost in v1.2. Source: spike 002a.
- **Vendor email composition (spike 001) targets `Vendor.PrimaryEmailAddr.Address` (QBO) and `Contact.EmailAddress` (Xero).** Both expose vendor email as a first-class field. Wave + FreshBooks do not — they store vendor names as free text. The QBO+Xero choice is also a vendor-email-feasibility choice. Source: spikes 001 + 002.
- **The `smb-audit` skill (Phase 4) must ALWAYS exit 0.** Non-zero exits trigger gbrain Minions' 3-attempt retry policy (1s/2s/4s backoff = ~7s wasted on a deterministic skill failure). Internal errors handled internally → write `concepts/audit-error.md` rather than throwing. Source: spike 003.
- **`scripts/seed.sh` must parse the `Result:` JSON line's `exit_code` field**, not `gbrain jobs submit --follow`'s own exit code (which is always 0 regardless of job outcome). Source: spike 003.
- **`bun` must be in PATH when invoking `gbrain`.** gbrain spawns its worker via `bun` internally. `scripts/seed.sh` + `scripts/demo-check.sh` should `export PATH="$HOME/.bun/bin:$PATH"` defensively. Source: spike 003.
- **v1.2 "Outbound Communications" leads with CPA-facing monthly reports**, not vendor-facing weekly emails. Audience swap eliminates 6 of 8 risks from spike 001 (recipient desirability, tone policing, multi-recipient deliverability, per-vendor template gymnastics). Anomalies are the headline, not the omission. Source: spike 004.
- **PDF archival format = `@media print` stylesheet on the HTML email**, not Puppeteer / Cloud Run / a PDF library. Browsers print to PDF natively; CPAs cmd+P to archive. Source: spike 004.
- **Per-tenant `sourceId` MUST be registered as a `sources` row BEFORE the first `importFromContent` call.** gbrain enforces FK `pages.source_id → sources(id)`; any QBO ingest job using `sourceId='qbo-<userId>'` against an un-registered source throws `PostgresError: pages_source_id_fkey`. Phase 7's OAuth-connect handler must `INSERT INTO sources (id, name, config) VALUES ($1, $2, $3::jsonb) ON CONFLICT (id) DO NOTHING` before enqueuing the first ingest job. Source: spike 007.
- **`types/gbrain.ts` shim must expose `importFromContent` for Phase 7.** Add an `importFromContent(engine, slug, content, opts)` wrapper that delegates to `_load("import-file")` — same dynamic-import pattern as `createEngine`/`hybridSearch`. Runtime path proven by spike 007 (1.9s/page incl. one OpenAI embedding call). Source: spike 007.
- **Re-sync (Phase 7 D-08 "wipe-and-reingest") is one SQL: `DELETE FROM sources WHERE id = $1`.** The FK `ON DELETE CASCADE` sweeps every page + chunk + tag + link atomically (~120ms in spike). No per-slug iteration, no `deleteSource()` engine method needed. The destructive-confirm modal in 07-UI-SPEC.md is gating exactly the right primitive. Source: spike 007.
- **RLS is NOT the tenant-isolation primitive for QuickBrain.** gbrain enables RLS on every public table but the Supabase pooler role we connect as holds `BYPASSRLS`. Spike 005's "RLS on 41/41 tables" finding meant the DDL flag is on — it does NOT mean our app code is enforced. RLS is defense-in-depth against the Supabase `anon` role only. All tenant isolation lives in app-layer per-call `sourceId` scoping. Source: spike 010.
- **gbrain has no fail-safe default for `sourceId`.** Bare `engine.getPage(slug)` / `engine.deletePage(slug)` / `engine.listPages()` / `hybridSearch(engine, q)` without sourceId silently return / mutate / federate across all tenants. Silent leak class — no exception, no warning, no audit. The single-shared-engine pattern in `lib/gbrain/engine.ts` survives concurrent multi-tenant load (20 interleaved queries / 0 leaks) but only when every call site passes sourceId. Source: spike 010.
- **`lib/gbrain/tenant-scoped.ts` wrapper layer + ESLint ban on bare `engine.*` is required before Phase 7 lands.** Wrappers `tenantSafeGetPage(tenantId, slug)` / `tenantSafeHybridSearch(tenantId, q)` / `tenantSafeListPages(tenantId, filters)` resolve tenantId → sourceId via `lib/auth/resolve-tenant.ts` AND require both args. An ESLint rule bans bare `engine.getPage(` / `engine.deletePage(` / `engine.listPages(` outside `lib/gbrain/` so silent leak via call-site oversight is killed at compile time. Source: spike 010.
- **Default `GBRAIN_POOL_SIZE=10` is sufficient for v2.0.** Supabase free-tier pool + gbrain default max:10 pool sustains 200 concurrent simple queries (1.9s wall, 0 errors) and 10 concurrent Inngest-shaped 5-step jobs (688ms wall, 0 errors). Phase 7 latency dominator is the 1.9s OpenAI embedding call per page (spike 007), NOT pool contention. No pool tuning needed. Source: spike 008.
- **Every `engine.executeRaw` call MUST pass at least one $N parameter.** Parameterless calls hang indefinitely against the Supavisor transaction-mode pooler — statement_timeout doesn't fire because the query never reaches Postgres (stuck in postgres.js's client-side empty-params code path). Phase 7 lint rule: any `engine.executeRaw(template)` call with missing or empty `[]` second arg is an error; auto-fix by appending a sentinel parameter. Source: spike 008.
- **Vercel Fluid Compute cold-start tax is ~310ms.** Bun init + gbrain dynamic-import + Supabase pooler connect = ~310ms total. The remaining ~1.4s of "cold path" `/api/chat` latency is the OpenAI `text-embedding-3-large` API roundtrip — same cost on warm instances. Cold 1.75s mean / warm 1.17s mean / ratio 1.5×. Source: spike 009.
- **Phase 4 ships without warm-pooling.** The 310ms cold-start savings doesn't justify a scheduled keep-alive cron's operational complexity. Vercel Fluid Compute's instance reuse already handles 95%+ of requests. Real latency lever for Phase 9+ is a query-embedding LRU cache (skip the 1.2s OpenAI call on repeat queries). Source: spike 009.
- **Don't change `next.config.ts` `serverExternalPackages: ['gbrain']` in Phase 4.** Spike 009's 62ms gbrain-module-load timing assumes Bun loads gbrain as raw `.ts` at runtime. Webpack-bundling gbrain inflates this dramatically. Source: spike 009.
- **Chat UX should promise "typical 1-2 seconds" not "instant."** Even on a warm Vercel instance, every `/api/chat` makes an OpenAI embedding call (~1.2s mean). Show a typing indicator within 200ms via SSE so the user knows the system is alive while OpenAI is roundtrip-ing. Source: spike 009.
