Spike 010 — per-tenant engine context

PARTIAL ⚠ Architecture pivot Phase 7 blocker

HEADLINE FINDING: gbrain enables RLS on every table BUT the Supabase pooler role we connect as has BYPASSRLS. RLS does NOT protect QuickBrain from in-app code that forgets to pass sourceId. All tenant isolation lives in app-layer per-call sourceId scoping — and the failure mode of "forgot to pass sourceId" is silent: returns one tenant's row arbitrarily, no exception, no warning.

Two takeaways, one architectural pivot

✓ The design works (under load)

The single long-lived BrainEngine + per-call sourceId pattern from lib/gbrain/engine.ts survives:
  • Concurrent multi-tenant queries (20 interleaved, 0 leaks)
  • Slug collisions across tenants (composite key isolates)
  • Mixed read + write through the same engine
Phase 4 keeps the cheap single-engine pattern. No per-tenant engine pool needed.

✗ But every call site is a foot-gun

gbrain has no fail-safe default for sourceId. The bare engine methods (getPage, deletePage, listPages, hybridSearch) silently return / mutate / federate across all tenants if you forget to pass scope. The CLI assumes single-tenant; the multi-tenant QuickBrain context inverts that assumption.
Required structural change before Phase 7 lands:
  1. Introduce lib/gbrain/tenant-scoped.ts — wrapper functions tenantSafeGetPage(tenantId, slug) / tenantSafeHybridSearch(tenantId, q) / tenantSafeListPages(tenantId, filters) that resolve tenantId → sourceId via lib/auth/resolve-tenant.ts AND require both args.
  2. Add an ESLint rule banning bare engine.getPage( / engine.deletePage( / engine.listPages( outside lib/gbrain/. All app callers go through tenant-safe wrappers. Compile-time enforcement.
  3. Audit existing call sites NOW — grep every engine.getPage, engine.deletePage, engine.listPages, engine.getTags, hybridSearch across lib/, app/, scripts/ and confirm each passes a per-request sourceId. Phase 6 shipped without this audit; oversight = live leak.
