## QuickBrain Auth Runbook (Phase 5)

### Required Environment Variables

Three new env vars for auth. Add to `.env.local`:

```
# Generate with: openssl rand -hex 32
JWT_SECRET=<64-char-hex>
TOKEN_ENCRYPTION_KEY=<64-char-hex>
RESEND_API_KEY=<from-resend.com/api-keys>

# Optional — defaults to onboarding@resend.dev (Resend test address)
RESEND_FROM_ADDRESS=QuickBrain <noreply@yourdomain.com>

# Optional — defaults to http://localhost:3000
NEXT_PUBLIC_APP_URL=http://localhost:3000

# Toggle auth on/off
AUTH_ENABLED=0   # 0 = anonymous demo (v1.0); 1 = email sign-in required
```

### Enabling Auth (AUTH_ENABLED=1)

1. Set the three required env vars in `.env.local`.
2. Verify domain with Resend (resend.com dashboard → Domains → Add domain → add SPF + DKIM DNS records). Without a verified domain, Resend only sends from `onboarding@resend.dev` to pre-verified test addresses.
3. Set `AUTH_ENABLED=1` in `.env.local`.
4. Run `bun run demo-check` — all checks including auth env vars must pass.
5. Start dev server: `bun run dev`.
6. Visit `/sign-in`, enter your email, click the magic link.

### Seeding a Test User (Development)

The auth-smoke.ts script creates a test token directly via the DB — no email required. Run with:

```bash
bun run dev          # in one terminal
bun run auth-smoke   # in another terminal
```

To manually create a test user and obtain a valid session cookie for curl testing:
```bash
# 1. Open bun REPL
bun repl
# 2. Import and issue a token
const { issueMagicToken } = await import("./lib/auth/jwt.ts")
const { storeMagicToken } = await import("./lib/auth/magic-tokens.ts")
const { token, jti } = await issueMagicToken("test@example.com")
storeMagicToken(jti, "test@example.com", Math.floor(Date.now()/1000) + 900)
console.log(`http://localhost:3000/api/auth/verify?token=${encodeURIComponent(token)}`)
# 3. Open the URL in browser — you'll be signed in
```

### AUTH_ENABLED Toggle

| Value | Behavior |
|-------|----------|
| `AUTH_ENABLED=0` (default) | Anonymous `/onboard` flow works as v1.0. No sign-in required. `middleware.ts` passes all requests through. |
| `AUTH_ENABLED=1` | `/` redirects to `/sign-in`. `/dash/*` and `/api/qbo/*` require valid `qb_session` cookie. Anonymous `/onboard` route remains accessible (no gate on that path — by design for demo flexibility). |

### Panic-Reset with Real Users

When AUTH_ENABLED=1, panic-reset is gated:

```bash
# Will print ERROR and exit non-zero
bash scripts/panic-reset.sh

# Will list affected emails + prompt for "yes" confirmation
AUTH_ENABLED=1 bash scripts/panic-reset.sh --force-real-tenants
```

### Resend Domain Setup (Production Sends)

1. Log into resend.com → Domains → Add domain.
2. Add the two DNS records Resend provides (SPF TXT + DKIM TXT).
3. Click Verify — propagation typically takes 5-30 minutes.
4. Set `RESEND_FROM_ADDRESS="QuickBrain <noreply@yourdomain.com>"` in `.env.local`.

For testing only (before domain is verified): use `onboarding@resend.dev`. Resend delivers from this address only to emails you've pre-verified in the Resend dashboard.

### Running the Smoke Gates

```bash
# Mutex regression (no dev server needed, no API keys needed)
bun run mutex-smoke

# Auth E2E (requires dev server + RESEND_API_KEY + JWT_SECRET set)
bun run dev        # terminal 1
bun run auth-smoke # terminal 2
```

### Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| `/dash/*` accessible without sign-in | middleware.ts not found / wrong export name | Check `middleware.ts` is at repo root (not in app/) and exports `function middleware` (not `proxy`) |
| `bun:sqlite` crash in middleware | lib/auth/db.ts imported transitively from middleware.ts | middleware.ts must only import from "jose" and "next/server" — check for any lib/auth/* import |
| Magic link loops back to /sign-in | SameSite=Strict on session cookie | Cookie must be SameSite=Lax (cross-site email redirect) |
| Token redeemed twice | Pre-SELECT + UPDATE race | Must use single `UPDATE WHERE used=0` + check `result.changes` |
| `next build` fails: Cannot resolve 'bun:sqlite' | bun:sqlite not in serverExternalPackages | Add `serverExternalPackages: ["bun:sqlite"]` to next.config.ts |
