Create lib/gbrain/engine.ts with the following structure and behavior:

IMPORTS (from gbrain library — use the installed package, not a local path):
  import { createEngine } from "gbrain/engine-factory";
  import { hybridSearch } from "gbrain/search/hybrid";
  import { expandQuery } from "gbrain/search/expansion";
  import type { SearchResult } from "gbrain/types";
  import type { BrainEngine } from "gbrain/engine";

Do NOT import from "node:child_process". Do NOT import spawn or spawnSync.

ENGINE POOL (module-level, per-process):
A Map<tenantId: string, Promise<BrainEngine>> called `enginePool`. Storing a
Promise (not BrainEngine) prevents race conditions when two concurrent requests
call createGBrainEngine simultaneously for the same tenant.

function buildConfig(): { engine: "postgres", database_url: string }
  Reads GBRAIN_DATABASE_URL from process.env.
  Falls back to SUPABASE_DB_URL_POOLER.
  Throws a clear error if neither is set: "GBRAIN_DATABASE_URL or SUPABASE_DB_URL_POOLER must be set".
  Returns { engine: "postgres", database_url }.

export async function createGBrainEngine(tenantId: string): Promise<BrainEngine>
  If enginePool.has(tenantId), return enginePool.get(tenantId)! (await the promise).
  Otherwise:
    const config = buildConfig();
    const p = createEngine(config).then(engine => engine.connect(config).then(() => engine));
    enginePool.set(tenantId, p);
    return p;

export async function disconnectEngine(tenantId: string): Promise<void>
  If enginePool.has(tenantId):
    const engine = await enginePool.get(tenantId)!;
    await engine.disconnect();
    enginePool.delete(tenantId);

export type { SearchResult };

export async function queryInProcess(
  tenantId: string,
  question: string,
  opts?: { noExpand?: boolean }
): Promise<SearchResult[]>
  Get engine via createGBrainEngine(tenantId).
  Call hybridSearch with expandFn wired in (UNLESS opts?.noExpand is true):
    const results = await hybridSearch(engine, question, {
      expandFn: opts?.noExpand ? undefined : expandQuery,
      expansion: !opts?.noExpand,
    });
  Return results.

NOTES ON expandFn WIRING (INPROC-03 — critical):
  The CLI's query pipeline returned 21 results; bare hybridSearch returned 1.
  The difference: expandFn. Pass expandFn: expandQuery into HybridSearchOpts.
  expandQuery requires ANTHROPIC_API_KEY to generate alternatives; without it,
  it degrades to [originalQuery] (single query, same as --no-expand). This
  degradation is acceptable for development; the demo requires ANTHROPIC_API_KEY.
  The noExpand option mirrors the CLI's --no-expand flag used in onboarding warm-up.

GBRAIN_HOME consideration:
  In the CLI path, GBRAIN_HOME pointed to brains/<tenantId>/. With in-process
  Postgres, gbrain reads its config from the environment (GBRAIN_DATABASE_URL),
  NOT from a local config.json. Do NOT set GBRAIN_HOME in this module.
  The seed brain's config.json (engine: postgres) is only consulted by the CLI,
  not by library createEngine calls. createEngine takes the config object directly.
