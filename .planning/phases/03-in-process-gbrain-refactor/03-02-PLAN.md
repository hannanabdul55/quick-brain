MUTEX RE-EVALUATION (INPROC-05):
  Current role: withTenantLock serializes child-process spawns per tenant to
  prevent PGLite "database is locked" errors.
  New role (Postgres backend, in-process): Postgres handles concurrent reads.
  However, the in-process engine pool (Map<tenantId, Promise<BrainEngine>>)
  already prevents concurrent createEngine calls. The mutex still provides
  useful serialization for the onboarding init/import/embed sequence (sequential
  gbrain operations on the same brain). For query/think, the mutex is no longer
  strictly necessary — but removing it changes the call graph for onboarding too.
  DECISION: Keep withTenantLock. Change the comment in mutex.ts from
  "PGLite exclusive file lock serialization" to "in-process serialization for
  sequential gbrain operations per tenant (onboarding init/import/embed);
  query/think no longer require serialization but the lock is harmless and
  preserves the Phase 1 test contract". Do NOT change withTenantLock logic —
  the mutex-smoke test (tests/unit/gbrain/mutex.test.ts) must pass unchanged.

REPLACE query():
  Old: calls spawnGBrain(["query", question], ...) and returns stdout.
  New:
    import { queryInProcess } from "./engine.ts";
    export async function query(
      tenantId: string,
      question: string,
      opts?: Partial<SpawnGBrainOpts> & { noExpand?: boolean }
    ): Promise<string>

  Implementation:
    const results = await queryInProcess(tenantId, question, {
      noExpand: (opts as any)?.noExpand ?? false,
    });
    // Format results like the CLI: "[score] slug -- chunk snippet"
    if (results.length === 0) return "No results.\n";
    return results
      .map(r => `[${(r.score ?? 0).toFixed(4)}] ${r.slug} -- ${(r.chunk_text ?? "").slice(0, 100)}`)
      .join("\n") + "\n";

REPLACE think():
  Old: calls spawnGBrain(["think", question, "--model", model], ...)
  New:
    import { runThink } from "gbrain/core/think/index";
    (Note: import path. The gbrain package exports this from the "." root export
    or via a subpath. If "gbrain/core/think/index" does not resolve, try importing
    runThink from "gbrain" directly or check the gbrain package.json exports map.
    The think command in cli.ts does `import('./commands/think.ts')` which calls
    `runThink` from `'../core/think/index.ts'`. For in-process consumption, the
    correct import depends on whether gbrain exposes this subpath. Check exports:

    entry which re-exports from src/core/index.ts, or check if runThink is
    re-exported from ".". Adapt accordingly — if not directly accessible, read
    the gbrain root index to find the correct path.)

  export async function think(
    tenantId: string,
    question: string,
    opts?: { model?: string; timeoutMs?: number }
  ): Promise<GBrainResult>

  Implementation:
    const engine = await createGBrainEngine(tenantId);
    // Wrap in withTenantLock for the same serialization contract as before.
    return withTenantLock(tenantId, async () => {
      try {
        const result = await runThink(engine, {
          question,
          model: opts?.model ?? "haiku",
        });
        // Render the answer. runThink returns result.answer (the synthesized text).
        // Mirror the GBrainResult contract so the chat route works unchanged.
        return {
          code: 0,
          stdout: result.answer,
          stderr: result.warnings.join("\n"),
        };
      } catch (err: unknown) {
        return {
          code: 1,
          stdout: "",
          stderr: err instanceof Error ? err.message : String(err),
        };
      }
    });
