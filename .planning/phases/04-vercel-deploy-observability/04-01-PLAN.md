<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public internet → /api/health | Anyone can GET the endpoint — it is public and unauthenticated by design (uptime monitors) |
| Route Handler → Supabase Postgres | The DB probe opens a throwaway connection using a secret URL from env |
| Route Handler → Supabase Storage | The storage probe sends a HEAD request authorized with the service-role key |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Information Disclosure | `/api/health` JSON payload | mitigate | Payload carries only booleans, `latencyMs`, and a sanitized `detail` string — never the connection string, host, service-role key, or env values; verified by a `grep` acceptance criterion |
| T-04-02 | Information Disclosure | probe error-handling in `lib/health/probes.ts` | mitigate | Catch handlers produce a generic message; the DB-probe failure detail never echoes the `postgres://` URL; storage-probe detail never echoes the bucket URL or service-role key |
| T-04-03 | Denial of Service / cost amplification | `/api/health` probes | mitigate | Probes check reachability only (`SELECT 1`, storage `HEAD`) — never a `think()` / LLM call; each probe is wrapped in a ~2.5s timeout so a dead subsystem cannot hang the endpoint or amplify cost |
| T-04-04 | Denial of Service | shared gbrain engine pool | mitigate | The DB probe uses a throwaway `postgres` connection (`max: 1`, closed in `finally`) and never touches the app's `enginePool` — a probe cannot poison or exhaust production connections |
</threat_model>
