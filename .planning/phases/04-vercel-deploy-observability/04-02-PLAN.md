<objective>
Wire `@sentry/nextjs` into the app using the modern Next.js 15 instrumentation
file set so that both unhandled server errors (Route Handlers, Server Components)
and unhandled client errors (React render crashes) are captured and surface in
the Sentry dashboard.

Purpose: DEPLOY-04 requires Sentry error tracking. The two acceptance signals —
a captured server error and a captured client error — map to `onRequestError`
(exported from `instrumentation.ts`) and `global-error.tsx` respectively.
Output: the Sentry instrumentation file set, a Sentry-wrapped `next.config.ts`
that preserves the gbrain externalization, and a committed `.env.example`.

CRITICAL CONSTRAINT: `next.config.ts` currently carries the gbrain build-readiness
fix from commit c49a927 (`serverExternalPackages: ["gbrain"]` + a webpack
externals function). Wrapping it with `withSentryConfig` MUST preserve both —
losing them re-breaks the production build. The plan re-verifies `bun run build`
after the Sentry changes.
</objective>
