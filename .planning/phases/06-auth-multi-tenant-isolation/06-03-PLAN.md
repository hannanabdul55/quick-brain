<objective>
Build the magic-link authentication backend: token signing/verification, the
Resend email sender, the send-link route (with DB-backed rate limiting), the
verify route (atomic single-use consume + first-sign-in brain provisioning +
session establishment), the sign-out route, and the single
session-to-`source_id` chokepoint (`lib/auth/resolve-tenant.ts`). This satisfies
AUTH-01 (email magic link), AUTH-02 (single-use, time-limited), AUTH-04 (one
auto-provisioned brain per user), and AUTH-09 (per-email rate limiting).

Purpose: This is the auth engine. Plan 06-04 builds the UI and route protection
on top; plan 06-05 wires `resolveTenant` into the gbrain calls.
Output: Five `lib/auth/` modules and three route handlers.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser/email client -> /api/auth/send-link | Untrusted email + next param crosses here |
| email client -> /auth/verify | Untrusted token crosses here; email scanners may prefetch |
| browser -> /api/auth/sign-out | Session cookie crosses here |
| route -> gbrain sources table | Brain provisioning crosses into the shared gbrain DB |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-09 | Tampering | magic-link token | mitigate | jose HS256 with a >=32-byte `JWT_SECRET`; `jwtVerify` validates signature + expiry; tampered tokens return `reason: "invalid"` |
| T-06-10 | Elevation of Privilege | magic-link replay (TOCTOU) | mitigate | `consumeMagicLink` is a single atomic `UPDATE ... WHERE used=false AND expires_at>now()` with a `rows.count` check — two concurrent clicks cannot both win |
| T-06-11 | Denial of Service | send-link email flooding | mitigate | `wasRecentlyRequested` DB-backed rate limit (1/email/60s, D-09/AUTH-09) — persisted, survives serverless cold starts; 429 with no send |
| T-06-12 | Spoofing | open-redirect via `?next=` | mitigate | `isSafeNextPath` rejects `//` and scheme prefixes; `next` only appended/honored when it passes; never rendered as a link |
| T-06-13 | Information Disclosure | email/token in logs | mitigate | Routes log metadata only — never the email address or token text (mirrors chat/route.ts privacy precedent) |
| T-06-14 | Elevation of Privilege | attacker-supplied source id reaching a gbrain query | mitigate | `provisionBrain` is the only `sources` writer; the source id is generated server-side, never from request input; `resolveTenant` derives it from the session only |
| T-06-15 | Spoofing | session fixation | mitigate | A fresh opaque `randomUUID` session id is minted on every verify; the cookie is `HttpOnly` + `Secure` + `SameSite=Lax` (D-05) |
| T-06-16 | Tampering | magic-link prefetch by email scanners | accept | Single-GET consume is accepted; the `/auth/link-used` resend path (D-07) is the safety net — documented tradeoff (Pitfall 4 option b) |
</threat_model>
