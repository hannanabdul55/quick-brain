<objective>
Close the loop on multi-tenant isolation (AUTH-05): wire the session-derived
`source_id` from `lib/auth/resolve-tenant.ts` into all four
`app/api/tenants/[id]/*` routes, so every gbrain query/think/insight call is
hard-scoped to the authenticated user's brain. Replace the four routes'
slug-from-URL `tenant_not_found` lookup with session resolution (the folded
`tenant-registry-deploy-persistent` fix on the API side). Address the
engine-pool eviction gap (T-03-03). Finally, write the AUTH-05 cross-tenant
isolation test that proves — at the application boundary — that User A cannot
reach User B's data.

Purpose: This is the phase's headline guarantee. Plan 06-02 made the gbrain
paths source-scopable; plan 06-03 built the session chokepoint; this plan makes
every tenant-data route actually pass the session source through, and verifies
it. AUTH-05's mechanism is session-derived source-scoping (REQUIREMENTS.md
amended 2026-05-22) — the test verifies the application boundary, NOT gbrain RLS.
Output: Four updated routes, the engine-pool fix, and the isolation test.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> /api/tenants/[id]/* | URL slug is attacker-controllable; identity must come from the session |
| tenant route -> gbrain shared DB | The only inter-tenant boundary is the per-call `source_id` filter |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-22 | Information Disclosure | cross-tenant data read via chat/query | mitigate | Every gbrain call from a tenant route is hard-scoped to the session-derived `source_id` resolved by `resolveTenant()`; the D-12 patch scopes the `think` path; verified by the Task 2 isolation test |
| T-06-23 | Elevation of Privilege | attacker names another user's source_id | mitigate | Routes call `resolveTenant()` which takes NO source-id argument — the source is derived from the verified session only; the URL slug is never trusted for identity |
| T-06-24 | Spoofing | request authenticated as A reaching B's brain | mitigate | The single chokepoint (`resolve-tenant.ts`) means "can A reach B?" is answerable by inspecting one file; the isolation test asserts it |
| T-06-25 | Denial of Service | engine-pool connection leak under multi-tenant | mitigate | Engine pool collapsed to a single shared engine (scoping is per-call, not per-engine) — no per-user connection accumulation (closes the T-03-03 gap) |
| T-06-26 | Repudiation | unscoped insight/reset operation on a real tenant | mitigate | insights + reset routes scope to the resolved `sourceId`; reset no longer `rm -rf`s a filesystem brain dir for hosted tenants |
</threat_model>
