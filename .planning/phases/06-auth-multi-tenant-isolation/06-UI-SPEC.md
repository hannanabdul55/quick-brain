> confirmation, link-used/expired page, sign-out control). Generated by
> gsd-ui-researcher, verified by gsd-ui-checker.

> real. Reuse the existing centered-card layout (`app/page.tsx`,
> `app/onboard/page.tsx`) and the existing shadcn components. Do NOT introduce a
> new design system, new brand identity, or marketing pages — those are v2.1
> out-of-scope per PROJECT.md.

## Typography

Geist sans across all roles. Exactly 4 sizes, exactly 2 weights.

| Role | Size | Weight | Line Height | Tailwind / usage |
|------|------|--------|-------------|------------------|
| Display | 36px | 700 (bold) | 1.2 | `text-4xl font-bold tracking-tight` — landing `<h1>` only (`app/page.tsx`) |
| Heading | 20px | 600 (semibold) | 1.2 | shadcn `CardTitle` — "Sign in to QuickBrain", "Check your email", "This link can't be used" |
| Body | 16px | 400 (regular) | 1.5 | `CardDescription`, confirmation copy, landing paragraph (`text-base` / `text-lg` on landing) |

two declared weights. Label `font-medium` (500) and Display `font-bold` (700)
are pre-existing shadcn/landing conventions carried forward verbatim — do not
introduce any additional weight beyond these four already in the codebase.

## Color

Neutral grayscale only — the existing `base-nova` / `neutral` oklch token set in
`app/globals.css`. Light mode is the only theme this phase ships.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` `oklch(1 0 0)` (white) | Page background (`bg-background`) |
| Secondary (30%) | `--card` `oklch(1 0 0)` + `--muted` `oklch(0.97 0 0)` | Card surface, `text-muted-foreground` body copy |
| Accent (10%) | `--primary` `oklch(0.205 0 0)` (near-black) | Primary buttons only — see reserved list |
| Destructive | `--destructive` `oklch(0.577 0.245 27.325)` | Not used by this phase — no destructive actions exist here |

**Accent reserved for:** the primary CTA button fill on each screen and nothing
else —
1. `/sign-in` form: the "Send magic link" submit button
2. `/auth/link-used`: the "Resend magic link" button
3. `/`: the "Sign in" CTA button

Sign-out is a `variant="ghost"` or `variant="outline"` button (not accent) —
see Components Inventory. Links/secondary actions use `text-foreground` or
`buttonVariants({ variant: "outline" })`, never the accent fill.

**Error styling:** reuse the existing inline-error treatment from
`components/onboard/error-banner.tsx` —
`bg-red-50 border border-red-200 text-red-900 p-4 rounded-md`. Do NOT invent a
new error color; the project already standardized this red-tint banner. Inline
field errors under the email input use `text-sm text-red-900` (no banner box for
single-field validation).

## Interaction Contract

### `/sign-in`
- `form` state: single email `Input` + full-width "Send magic link" `Button`.
  Client-side validation: email format via `zod` (the project already uses
  `zod`; mirror `createTenantBodySchema` style). Invalid email → inline
  `text-sm text-red-900` message under the input; do not POST.
- `submitting` state: button `disabled`, label → "Sending…". Input `disabled`.
- `sent` state: replace the form with the confirmation card (see Copywriting).
  Show the address the link was sent to. Offer a "send again" affordance that
  respects the 60s rate limit (D-09) — if pressed inside the window, show the
  rate-limit message rather than re-sending.
- `error` state (request failed / network): show the `ErrorBanner` pattern with
  a "Try again" action that returns to `form` state.
- `?next=` param: read it on mount, carry it opaquely through the magic-link
  request so the post-verify redirect lands on the originally requested route.
  Never render `?next=` as visible copy.

### `/auth/link-used`
- Static explanatory card. One primary action: "Resend magic link". On click →
  `resending` (button disabled, "Sending…") → `resent` (swap card body to the
  same "Check your email" confirmation copy used by `/sign-in`'s `sent` state).
- This page is reached when a magic-link token is expired (15-min TTL, D-07) or
  already consumed (single-use, D-07). The copy must not blame the user.

### Sign-out control (dashboard)
- Placed in the dashboard top-right. The dashboard (`/dash/[id]`) currently has
  no header chrome — Phase 6 adds a minimal header row holding the sign-out
  button. Keep it minimal: a single `ghost`/`outline` `Button` with a `LogOut`
  icon + "Sign out" label, right-aligned, `text-sm`.
- `idle` → on click → `signing-out` (disabled, "Signing out…") → server clears
  the `qb_session` cookie and deletes the session row → redirect to `/sign-in`.
- No confirmation dialog. Sign-out is non-destructive (data persists; D-04
  server-side session revocation only) — a confirm step would be friction
  without a safety payoff.

### `/` landing
- Repurpose the existing single CTA: change destination from `/onboard` to
  `/sign-in` and change the label (see Copywriting). Keep the existing
  `text-4xl` headline, `text-lg text-muted-foreground` paragraph, and large
  button treatment from `app/page.tsx`. No other landing changes.

## Accessibility Contract

- Email input has an associated `<label htmlFor>` — mirror the
  `app/onboard/page.tsx` label pattern (`text-sm font-medium text-foreground`).
- `autoFocus` the email input on `/sign-in` `form` state.
- The `submitting`/`resending` states use `disabled` + label change; ensure the
  disabled button still has an accessible name.
- Inline errors are programmatically associated with the input
  (`aria-describedby`) so screen readers announce them.
- The `?next=` redirect must only ever point to a same-origin path — validate
  server-side; never render user-controlled redirect targets as links.
- Color is never the sole error signal — error copy always accompanies the
  red tint.
