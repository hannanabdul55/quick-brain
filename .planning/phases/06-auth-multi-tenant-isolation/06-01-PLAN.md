<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app code -> Supabase Postgres | All SQL crosses here; the `postgres` connection holds the BYPASSRLS service role |
| operator shell -> setup-auth-tables.ts | DB_URL secret read from env; must never be echoed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Tampering | SQL queries in store.ts/session.ts | mitigate | All queries use postgres.js tagged-template parameterization; no string concatenation of any input (mirrors lib/jobs/store.ts T-05-05) |
| T-06-02 | Information Disclosure | DDL script / store errors | mitigate | Sanitized fatal handler strips `postgres://` URLs; error text sliced to 500 chars before any log; never log email or session id |
| T-06-03 | Spoofing | app.sessions.id | mitigate | Session id is `node:crypto.randomUUID()` (122-bit, cryptographically random — unguessable, prevents session fixation/hijacking) |
| T-06-04 | Elevation of Privilege | app.* tables caught by gbrain auto-RLS trigger | mitigate | All three tables in the `app` schema (not `public`); RLS-visibility probe in the DDL script fails loudly if the trigger still fires |
| T-06-05 | Repudiation | magic_links consume | mitigate | `used_at timestamptz` records consume time; atomic UPDATE prevents double-consume (full TOCTOU mitigation in plan 06-03) |
| T-06-SC | Tampering | `bun add jose resend` | mitigate | Task 1 blocking-human checkpoint verifies both `[ASSUMED]` packages against npmjs.com + repo URL + empty postinstall before install |
</threat_model>
