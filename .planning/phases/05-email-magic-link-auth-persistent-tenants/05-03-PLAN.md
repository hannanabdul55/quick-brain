Key constraints from RESEARCH.md:
- §4: middleware.ts MUST use jose jwtVerify directly. Do NOT import from lib/auth/jwt.ts or lib/auth/db.ts — both have bun:sqlite in their transitive dependency graph. lib/auth/jwt.ts itself does NOT import bun:sqlite, but lib/auth/index.ts re-exports lib/auth/magic-tokens.ts which imports lib/auth/db.ts. Safest approach: inline the jose import in middleware.ts rather than relying on the lib/auth barrel.
- §4: middleware.ts is for Next.js 15.3.2. Use `export function middleware()` NOT `export function proxy()`. File lives at repo root (same level as app/).
- §4: config.matcher limits middleware to ["/dash/:path*", "/api/qbo/:path*"] — static assets, /sign-in, /api/auth/* are NOT in the matcher.
- §9: AUTH_ENABLED=0 → middleware short-circuits to NextResponse.next() immediately. app/page.tsx uses config.authEnabled flag for hero vs redirect.
- §10 Pitfall 11: Do NOT use proxy.ts (Next.js 16). This project is 15.3.2.
- §4: next param: middleware encodes original path as ?next= on redirect to /sign-in. sign-in page reads this param and includes it in the send-link POST body so the magic link carries it to /api/auth/verify (handled in Plan 02).
- UI: use shadcn/ui components (Button, Input, Card) and Tailwind classes. Keep UI functional and clean — no design system invention needed.

Create middleware.ts at the repo root (NOT inside app/). Per RESEARCH §4 exact pattern:
- Import only from "jose" and "next/server". DO NOT import from any lib/auth file.
- Define `const secret = new TextEncoder().encode(process.env.JWT_SECRET!)` at module scope.
- Define `const PROTECTED_PREFIXES = ["/dash", "/api/qbo"] as const`.
- `export async function middleware(request: NextRequest): Promise<NextResponse>`:
  1. `const { pathname } = request.nextUrl`.
  2. `const authEnabled = process.env.AUTH_ENABLED === "1"`. (Use process.env directly — config.ts cannot be imported here without risk of transitive bun:sqlite.)
  3. If `!authEnabled`: return `NextResponse.next()`.
  4. `const isProtected = PROTECTED_PREFIXES.some((p) => pathname.startsWith(p))`.
  5. If `!isProtected`: return `NextResponse.next()`.
  6. `const sessionCookie = request.cookies.get("qb_session")?.value`.
  7. If no cookie: build redirect URL `new URL("/sign-in", request.url)`, set `next` searchParam to `encodeURIComponent(pathname)`, return `NextResponse.redirect(redirectUrl)`.
  8. Try `await jwtVerify(sessionCookie, secret, { clockTolerance: "30s" })`. Return `NextResponse.next()` on success.
  9. Catch: delete cookie on response (`response.cookies.delete("qb_session")`), redirect to `new URL("/sign-in?error=session-expired", request.url)`.
- Export config: `export const config = { matcher: ["/dash/:path*", "/api/qbo/:path*"] }`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → middleware.ts | Untrusted qb_session cookie read from NextRequest.cookies |
| middleware.ts → jose | JWT verification in Edge Runtime — no DB access |
| app/sign-in/page.tsx → /api/auth/send-link | Client component POSTs email; validated by zod in route handler |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-12 | Spoofing | middleware.ts cookie bypass | mitigate | jwtVerify requires valid HMAC signature; forged cookies throw JWSInvalid; expired cookies throw JWTExpired; both cause redirect to /sign-in |
| T-05-13 | Tampering | middleware.ts bun:sqlite transitive import | mitigate | middleware.ts imports ONLY from "jose" and "next/server"; verified by grep: `grep -v "lib/auth" middleware.ts` |
| T-05-14 | Information Disclosure | /sign-in?error= param | accept | Error params reveal link-expired vs invalid-link distinction; acceptable UX tradeoff for a magic-link app; no credential leakage |
| T-05-15 | Elevation of Privilege | AUTH_ENABLED=0 bypass | mitigate | middleware short-circuits via `process.env.AUTH_ENABLED === "1"` check; when 0, all /dash/* requests pass through; this is intended behavior (anonymous demo mode) |
| T-05-16 | Repudiation | next= redirect open redirect | mitigate | verify route (Plan 02) validates next param starts with "/" before redirecting; relative paths only — no external URLs accepted |
| T-05-17 | Tampering | Next.js proxy.ts confusion (Pitfall 11) | mitigate | File named middleware.ts, export named middleware — confirmed correct for Next.js 15.3.2 |
</threat_model>
