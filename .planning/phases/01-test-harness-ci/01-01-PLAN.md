  <name>Task 1: Install vitest and configure vitest.config.ts with opt-in integration project</name>
  <files>vitest.config.ts, package.json</files>
  <action>
    Run `bun add -D vitest` to add vitest as a dev dependency. Do NOT add
    @vitest/coverage-v8 — coverage is not required by this phase.

    Create `vitest.config.ts` at the repo root. Use `defineConfig` from vitest/config.
    Configure two Vitest "projects" (Vitest workspace / inline projects):

    Project 1 — "unit" (default, always runs):
    - name: "unit"
    - include: ["tests/**/*.test.ts"] — picks up tests/ directory (to be created in Task 2)
    - exclude: ["tests/integration/gbrain/**"] — excludes the gbrain-spawning tests
    - environment: "node"
    - No special env vars needed

    Project 2 — "gbrain-integration" (opt-in, skipped unless RUN_INTEGRATION=1):
    - name: "gbrain-integration"
    - include: ["tests/integration/gbrain/**/*.test.ts"]
    - The tests themselves use `describe.skipIf(!process.env.RUN_INTEGRATION)` as
      an additional guard, but exclude them at the config level too for clarity.

    Set global vitest options:
    - testTimeout: 10000 (10s default — mutex tests need ~1s, tenant tests slightly more)
    - globals: false (explicit imports are cleaner for a new suite)
    - pool: "forks" (avoids shared state between test files — important for mutex tests)

    After creating vitest.config.ts, add two scripts to package.json:
    - "test": "vitest run" — CI mode (runs once, exits with pass/fail)
    - "test:watch": "vitest" — interactive watch mode for development

    Do NOT modify any existing scripts. Add only "test" and "test:watch".

    Verify the config parses: `bun -e "import('./vitest.config.ts').then(() => console.log('OK'))"`.
  </action>
  <verify>
    <automated>grep -c '"test"' package.json | grep -v "^0$" && grep "vitest" vitest.config.ts && echo "PASS: vitest installed and configured"</automated>
  </verify>

    - No existing package.json scripts were removed or modified
  </done>

      "unit" Vitest project and included in every `bun run test` run

    Create `.github/workflows/ci.yml`. The workflow must:
    - name: "CI"
    - on: push (branches: [main]) and pull_request (branches: [main])
    - jobs: one job named "test" running on ubuntu-latest
    - steps:
      1. actions/checkout@v4
      2. oven-sh/setup-bun@v2 (no version pin — picks up the repo's bun version)
      3. `bun install --frozen-lockfile`

      5. `bun run lint` — ESLint via next lint; fails on lint errors
      6. `bun run test` — Vitest run; fails on any failing test
    - Do NOT set RUN_INTEGRATION=1 — gbrain-spawning tests must be excluded from CI
    - Do NOT add OPENAI_API_KEY, ANTHROPIC_API_KEY, or SUPABASE_* secrets to this
      workflow — Phase 2 handles infra secrets; Phase 1 CI must run without them

    Env vars to set at the job level:
    - NODE_ENV: test

    No caching configuration needed — bun install is fast enough for a demo project.
  </action>
