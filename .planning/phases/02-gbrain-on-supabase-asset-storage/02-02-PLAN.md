<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SUPABASE_SERVICE_ROLE_KEY → lib/storage/supabase.ts | Service role key has admin-level storage access. Passed in env; must not be logged or surfaced in errors. |
| gbrain files subsystem → Supabase Storage bucket | Files uploaded via gbrain files upload or lib/storage are sent over HTTPS to Supabase. No authentication bypass is possible. |
| gbrain.yml → gbrain storage-config.ts | gbrain.yml is committed and controls which directories are db_tracked vs db_only. An overlapping config throws StorageConfigError — fail-loud is the correct behavior. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02B-01 | Information Disclosure | SUPABASE_SERVICE_ROLE_KEY in lib/storage/index.ts | mitigate | Key is read from process.env only, never logged or returned in API responses. lib/storage/ functions do not log credentials. Note in code: throw an Error with a generic message if missing, not one that echoes the key. |
| T-02B-02 | Elevation of Privilege | Service role key bypasses RLS | mitigate | The service role key bypasses Supabase RLS for storage. lib/storage/ is used ONLY for binary assets (gbrain files). Text pages live in Postgres under gbrain's own pooler connection (which uses the postgres role, not service role). Keep the service role key out of the gbrain child-process env — lib/storage/ is app-layer only. |
| T-02B-03 | Tampering | gbrain.yml misconfiguration (tier overlap) | mitigate | gbrain's StorageConfigError throws on overlap. If db_tracked and db_only lists share a path, gbrain exits non-zero. The executor tests gbrain storage status to confirm no errors. |
| T-02B-04 | Information Disclosure | SUPABASE_URL / SERVICE_ROLE_KEY missing in ephemeral env | mitigate | createStorage() throws a clear, credential-free error: "SUPABASE_URL and SUPABASE_SERVICE_ROLE_KEY required for STORAGE_BACKEND=supabase". Does not echo partial values. |
| T-02B-05 | Denial of Service | Ephemeral filesystem / writable brains/ at runtime | accept | Phase 2 scope: seed brain queries are FS-read-only (config.json only). New tenant onboarding still writes to local disk — documented as Phase 5 hand-off. No new risk introduced by Phase 2. |
| T-02B-SC | Tampering | npm/pip/cargo installs | accept | No new package-manager installs in this plan. Supabase Storage is accessed via raw fetch — no new dep. |
</threat_model>
