<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| env → gbrain child process | GBRAIN_DATABASE_URL (pooler URL with password) flows from process.env into every spawned gbrain child. If the env is leaked (e.g., in an error message), the password is exposed. |
| config.json → git | brains/seed/.gbrain/config.json is committed. Any field containing a password would leak into git history permanently. |
| migration CLI → Supabase | gbrain migrate writes the password to config.json in plaintext. This is the moment of highest credential-leakage risk. |
| gbrain stdout/stderr → logs | Error messages from gbrain may echo the connection string (including password) into logs, stdout, or crash reports. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | brains/seed/.gbrain/config.json | mitigate | Sanitize config.json immediately after every migration run — strip database_url field before any git add. Task 1 + Task 2 test enforce this. |
| T-02-02 | Information Disclosure | lib/gbrain/client.ts env spread | mitigate | GBRAIN_DATABASE_URL is injected via env into child process — never logged. The existing onStderrLine callback is user-visible; if gbrain ever echoes the URL in stderr, it would leak. Add a note to audit stderr logging if gbrain emits connection errors (redact URLs before surfacing). |
| T-02-03 | Information Disclosure | gbrain error messages | accept | gbrain's config.ts:redactUrl() masks passwords in `gbrain config show` output. For crash messages, gbrain does not currently redact — low risk for a local demo; document that Route Handlers should not surface raw gbrain stderr to users. |
| T-02-04 | Elevation of Privilege | RLS misconfiguration | mitigate | Spike 005 confirms gbrain auto-enables RLS on all 41 tables + installs an event trigger. gbrain doctor verifies RLS state. Run doctor after every migration. Phase 5 (multi-tenant) will rely on per-tenant RLS scoping; Phase 2 only needs to confirm RLS is on (single-user demo). |
| T-02-05 | Tampering | Migration data loss | mitigate | gbrain migrate --to supabase is self-verifying (re-counts pages + embeddings on target). Spike 005 confirmed 48/48 pages, 100% embeddings. If counts mismatch, abort and investigate before committing config.json. |
| T-02-06 | Denial of Service | SUPABASE_DB_URL_DIRECT absent at runtime | mitigate | seed.sh guards: exits with a clear error if SUPABASE_DB_URL_DIRECT is unset in Postgres mode. client.ts falls back gracefully if SUPABASE_DB_URL_POOLER is unset (inherits GBRAIN_DATABASE_URL from parent env). |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No new package manager installs in this plan. All tools (gbrain, bun, vitest) are already installed. N/A. |
</threat_model>
