<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → /api/connections/quickbooks/resync | Resync action goes through the API route with resolveTenant() — not a direct Inngest call |
| DashLayout server-side status read | qbo_connection_status read server-side from session-resolved userId — never from URL param |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-25 | Spoofing | ReconnectBanner renders on revoked status | accept | Status is server-side read from session-resolved userId — cannot be spoofed by URL params |
| T-07-26 | Information Disclosure | sync-progress page jobId | accept | jobId is a UUID in the URL query param; it is not a secret — it only lets the user poll their own job status; resolveTenant() in the jobs poll route validates ownership |
| T-07-27 | Tampering | Re-sync confirmation modal | mitigate | AlertDialog requires explicit destructive confirm ("Yes, re-sync") before POST is sent; UX matches D-08 destructive-confirm requirement |
| T-07-28 | Tampering | Disconnect confirmation modal | mitigate | AlertDialog requires explicit confirm ("Disconnect") before POST; user must consciously choose disconnection |
| T-07-SC | Tampering | shadcn alert-dialog (official registry) | accept | Official shadcn registry; no vetting gate required per RESEARCH Package Legitimacy Audit |
</threat_model>
