<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OAuth callback route → Inngest event | Event payload must contain only identifiers (userId, brainSlug, sourceId, realmId) — never QBO API data |
| Inngest job → QBO API | All QBO fetches happen inside step.run(); tokens are decrypted inside the step — never in event payload |
| importFromContent sourceId | Must be session-derived brain_id; missing or wrong sourceId is a cross-tenant isolation failure |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-16 | Elevation of Privilege | importFromContent sourceId | mitigate | CRITICAL: sourceId is passed from event.data.sourceId (set by OAuth callback from resolveTenant()); never computed inside the job from request params. Grep of ingest.ts must show sourceId flowing from event.data, not from a URL param. |
| T-07-17 | Information Disclosure | Inngest event payload | mitigate | Event payload contains only identifiers (jobId, userId, brainSlug, sourceId, realmId) — verified by RESEARCH Pitfall 6 discipline. No token values in event payload (encrypted tokens fetched inside step 1 from Postgres). |
| T-07-18 | Denial of Service | ConnectorRevokedError retry | mitigate | ConnectorRevokedError is NOT re-thrown after failJob — prevents Inngest from retrying a revoked connection (which would burn all 2 retries against Intuit for a permanent error) |
| T-07-19 | Tampering | qbo_last_synced_at UPDATE | accept | UPDATE uses userId from event.data (set server-side by session) + tagged-template SQL — no injection vector |
| T-07-SC | Tampering | npm/pip/cargo installs | accept | No new npm packages installed |
</threat_model>
