  <action>
    Create `scripts/bench-gbrain.ts` with the `#!/usr/bin/env bun` shebang, matching the
    structure of `scripts/concurrent-smoke.ts`. It imports `queryInProcess` from
    `@/lib/gbrain/engine`, `think` from `@/lib/gbrain/client`, and `SEED_TENANT_ID` from
    `@/lib/gbrain/paths`. It measures three operations against the seed tenant
    (`SEED_TENANT_ID = "seed"`):

    - `query` — `queryInProcess(SEED_TENANT_ID, "What was weird about March?")`, n=30.
    - `think` — `think(SEED_TENANT_ID, "What was weird about March?", { model: "haiku" })`, n=10.
    - `import` — measure the onboarding/import path. Because `onboard()` still uses the
      local-PGLite `spawnGBrain` path and creates throwaway brains (RESEARCH Open Q3),
      the executor MUST pick ONE of: (a) call `onboard({ tenantId: 'bench-' + Date.now() })`
      n=3 against throwaway local brains, or (b) skip a live `import` benchmark and instead
      record import duration from the most recent `scripts/seed.sh` run logs. Document the
      chosen approach inline in the script and in the threshold doc.

    Implement a `percentile(samples, p)` helper (sort ascending, index = ceil(p/100 * len) - 1,
    clamp at 0) and a `timeIt(fn)` helper using `performance.now()`. For each operation:
    run ONE warm-up iteration and discard it (it pays cold connection-pool + gateway init),
    then collect N timed samples, then print one line: `<label>: n=<N> p50=<ms> p95=<ms> max=<ms>`.
    Use top-level `await`. On any thrown error, print it and `process.exit(1)`.
    Hard-code the chosen N values as named constants so the run is reproducible.
  </action>
